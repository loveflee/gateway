## 實作與安全契約

`coil_groups` 的 member 必須連續、不 overlap，並且每個 member 仍是既有 `write_fc: 5` 單路 switch。群組 command 僅接受 profile 定義的名稱，再轉為完整 bool vector；未做 read-modify-write。verify 使用群組指定的既有 `read_coils`（FC01 0..7）並沿用既有 bit decoder，因此一次同步 `switch_0`..`switch_7`，再將 group slice 逐 bit 與 target 比對。

任何未命名 vector、缺 member 或單一 bit 不符都回 `__UNMATCHED__`；isolated test 讓 `[ON, OFF, ON, ON]` 分別翻轉四個 bit，四次全為 sentinel。以實際 `_process_write()` mock 路徑確認：精確命中只發布一次完整 state；sentinel 會寫入／驗證重試三次、發布次數為零。這封住 FC15 group 進入既有 `None` 成功分支的路徑，無須改動 BusMaster。

Native TCP driver 現在只接受正確 MBAP envelope 及 write echo：FC05/06 echo address+value；FC15/16 echo address+quantity。wrong transaction、protocol、length、UID、FC、address、value、quantity、short frame 和 FC05/06/15/16 exception 都不可回 True。

## 可觀測性與資料流黑洞檢查

isolated discovery 比對證明原八個 switch 的 entity id、unique id、name、state/command topic、ON/OFF payload、availability、device identity 皆 byte-for-byte 相同；新增加的只有 profile 宣告的兩個 select (`group_01`、`group_234`)。正式 command 的 log 顯示 group／switch 均由 `[Command]` 到 `寫入驗證成功`，MQTT state 亦達到 exact target。因此 HA observable、MQTT observable 及 production closed loop 均 PASS。

對新路徑搜尋與逐段審查 `None`、`return`、`except`、`continue`、publish 和 ACK 分支：MBAP malformed ACK 無成功出口；exception 回 False；group matcher 沒有 `None` 正常回傳；partial vector 是 sentinel；BusMaster 只在 exact `_values_equal` 後 publish success；validator 不靜默放行。**Data Flow Black Hole: NONE（FC15 新路徑）**。不將此結論擴大宣稱為未改動 legacy code 的全面語意重構。
