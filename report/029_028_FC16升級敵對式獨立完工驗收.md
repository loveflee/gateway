## 五、第五關：Word / Byte Order → **PASS**（本關為敵對重點）

### 語意對稱性（非只讓 oracle 過）

| 轉換 | read `_unpack_value` (len==4) | write `_apply_write_word_order` | 是否對合 |
|---|---|---|---|
| `swap`/`word_swap` | `chunk[2:4]+chunk[0:2]` | `chunk[2:4]+chunk[0:2]` | ✅ 自反 |
| `byte_swap` | `[1][0][3][2]` | `[1][0][3][2]` | ✅ 自反 |
| `little` | `chunk[::-1]` | `chunk[::-1]` | ✅ 自反 |
| `big`/預設 | 不轉換 | 不轉換 | ✅ |

三者皆為**對合（self-inverse）**。read 的語意是 `V = unpack(T(B))` ⇒ `B = T(pack(V))`；write 送出的正是 `T(pack(V))` —— **即設備回傳同一數值時會送出的 bytes**,語意正確。

### 固定 pattern `0x12345678` 實測

```
big        register bytes = 12 34 56 78
little                     78 56 34 12
swap                       56 78 12 34
word_swap                  56 78 12 34
byte_swap                  34 12 78 56
```

### encode → 模擬設備保存 → decode round-trip

`uint32` / `int32` / `float32` × 五種 order = **15 組全部正確還原**：

```
uint32  305419896 → 12 34 56 78 → 305419896   (big)
uint32  305419896 → 78 56 34 12 → 305419896   (little)
int32      -123456 → 1D C0 FF FE → -123456    (swap)
float32        1.5 → C0 3F 00 00 → 1.5        (byte_swap)
…（15/15 全通過）
```

### ⚠️ 一項語意不對稱（**非本輪回歸**,僅記錄）

read 對 `len==4` **不處理 `dcba`**（落到 big）；write 則**明確拒絕** `dcba`。
現行全部 profile **無** 32-bit `dcba` sensor（已掃描 10 個 profile）。改動前該情況會靜默截成 16-bit（更糟）,故非回歸。建議日後統一 read/write 對 `dcba` 的定義。
