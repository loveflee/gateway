# GenericAdapter FC16 升級後續注意事項

日期：2026-08-11
依據：Report 026 / 027 / 028 / 029

## 一、目前狀態

FC16 本輪升級：

**PASS WITH LIMITATIONS**

已完成：

* FC16 `quantity=2`
* `uint32`
* `int32`
* `float32`
* `big/default`
* `little`
* `swap / word_swap`
* `byte_swap`
* 32-bit 完整 write → ACK → verify → decode
* overflow / NaN / Inf 防呆
* PyModbus byte-for-byte oracle 驗證
* legacy FC01～06 / FC16 count=1 回歸驗證
* 雙 master legacy verify 行為保持一致

未發現本輪新增 regression。

---

## 二、目前尚未生效

驗收時：

* `generic_adapter.py` 已修改
* 執行中的 Gateway process 仍載入舊版 Adapter
* 尚未重啟 Gateway

因此正式生效前需要：

1. 重啟 Gateway。
2. 確認正常啟動、profile 全部載入成功。
3. 至少觀察一輪完整 poll rotation。
4. 執行一次既有、安全的 legacy 16-bit 寫入。
5. 確認 write → ACK → verify 正常。
6. 確認 HA state / availability 正常。
7. 確認沒有新增異常 offline / timeout / decode error。

雙 master 造成的既有 collision / RX noise / CRC 搜尋失敗屬刻意壓力測試基線，本身不列為此次 regression。

---

## 三、32-bit FC16 實機驗證

目前：

**NOT TESTED**

原因：

現場沒有已確認安全的 32-bit writable register。

禁止為了測試：

* 猜 writable address
* 寫未知 register
* 修改 production profile 硬測

未來取得明確安全的 32-bit writable register 後，再單獨補：

`uint32 / int32 / float32`

實機：

`write → ACK → verify read → decode → compare`

## 四、DCBA 語意不對稱

目前存在一項歷史語意問題：

### 32-bit Read

`dcba` 沒有專門處理，目前實際落入 `big/default` 行為。

### 32-bit Write

新版 Adapter 遇到 `dcba` 會明確拒絕：

`ValueError`

因此目前：

**read / write 對 `dcba` 的定義不對稱。**

### 目前影響

**無現場影響。**

已掃描目前 10 個 production profiles：

沒有 32-bit sensor 使用 `dcba`。

因此：

* 不是 FC16 本輪 regression
* 不影響目前設備
* 不需要現在修改

### 後續處理

未來若有設備需要 `dcba`：

先確認專案要採用的正式 DCBA 定義，再統一：

* read codec
* write codec
* tests
* validator

禁止只修 write 或只修 read。

## 五、map_validator 下一輪處理

`map_validator` 本輪刻意沒有修改。

### 用途

Adapter 是：

> Profile 已經載入後，真正執行 Modbus 操作時的最後防線。

Validator 則是：

> Profile 載入時的入口安檢。

例如 profile 寫：

`FC16 + uint64`

目前新版 Adapter 會在實際 command 發生時拒絕。

Validator 收緊後，可以在 profile 載入階段就發現：

> 此設定目前 GenericAdapter 不支援。

避免錯誤設定活到 runtime 才爆。

### 下一輪建議

獨立進行：

**GenericAdapter ↔ map_validator 規則一致性審查**

先審查，不直接修改。

至少確認：

* FC05 合法設定
* FC06 合法設定
* FC16 legacy 16-bit
* FC16 32-bit
* datatype
* length
* word_order
* link_sensor
* same-name sensor fallback
* unsupported datatype
* unsupported word order

最高原則：

**目前所有合法 production profiles 必須繼續 PASS。**

Validator 只能提早攔截真正不可能正確執行的設定，不得因規則過度嚴格導致現有合法 profile 無法載入。

---

## 六、本輪刻意不做的功能

目前不需要為了「完整 Modbus」繼續擴張。

暫不實作：

* FC15 — Write Multiple Coils
* FC22 — Mask Write Register
* FC23 — Read/Write Multiple Registers
* FC43
* `uint64`
* `int64`
* `float64`
* vendor-specific FC
* PyModbus production dependency

原則：

**有實際設備需求再補。**

目前 GenericAdapter 已足以涵蓋主要家用及一般 Modbus 使用場景。

特殊／非標準設備仍可使用專用 Adapter。

## 最終原則

> GenericAdapter 本輪 FC16 軟體升級已通過獨立敵對驗收。

目前不要繼續擴張 FC。

先讓新版正式載入並驗證既有設備。

`map_validator`、DCBA、其他 FC 與 64-bit 功能全部拆成獨立議題，遵守：

**先審查 → 證明需求/缺口 → 最小修改 → 回歸驗證 → 實機驗收。**
