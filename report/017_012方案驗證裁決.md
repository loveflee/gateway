# 017：012 Host-counter 方案實測裁決

## 裁決

**PASS／採用（限於本文驗證的修正版 Host-counter 設計）。** 6 組隔離測試、6 組通過、0 失敗；所有指定外部可觀測行為均成立。

這不是「目前 production 已有此功能」的宣告：靜態檢查確認現況仍會清 Discovery、沒有 executor guard 或 Host counter。故此裁決是**方案可採用**，實作後仍須以 listen 現場再驗收。

## 基線與方案邊界

- 現況仍為連續 3 次、每次 2 秒後熔斷（`src/listen_master.py:76-78, 209-224`），且接著 unregister、清 Discovery、重建 executor（`:231-244`）。
- `Gateway.unregister_device()` 的 cleanup 會發 retained 空 Discovery（`src/main.py:351-370`）；HA availability cache 初始為 `None`，重連補發會直接略過（`src/ha_manager.py:53-89`）。所以修正版必須在 listen 註冊時先發 offline。
- Compose 已有 `restart: unless-stopped` 且 `profile` 已是 rw host bind mount（`docker-compose.yaml:6,17-20`）；可用 `/app/profile/.listen-watchdog.json` 與 `.lock`，不用新增 Compose mount。現行 `profile/config.yaml` 沒有 listen 設備，故無硬體實測。

執行：

```bash
timeout 90 python3 -u scratch/validation_017/harness.py \
  > scratch/validation_017/out/run.log \
  2> scratch/validation_017/out/run.err
```

實際輸出：`exit=0`、`validation_017: PASS (6/6)`；完整結構化結果在 `scratch/validation_017/out/results.json`。

測試採用 fake driver、bounded hanging/valid JKBMS adapter、mock retained broker；`os._exit(75)` 僅記錄為 exit decision，沒有讓測試程序退出。真實 2 秒 timeout 合約以靜態檢查確認；為快速測試，fake timeout 縮短為 5 ms，Docker arming 仍以原始 3×2=6 秒計算。

## 可採用的最小修正版

1. `src/listen_master.py`：加入約 50–70 行的 status helper（sidecar `fcntl.flock`、同目錄 temp→fsync→`os.replace`→directory fsync）。初始讀到壞檔／`locked`／count≥3 時設 `_decoding_disabled`，不可寫也鎖定且保留 process/WebUI。
2. 同檔：`register_device()` 先 `ha_manager.set_availability(False)`；在 `run_in_executor()` 前 guard（現位置 `src/listen_master.py:204-212`）；熔斷時只 `_force_all_offline()`，**移除** `:231-244` 的 unregister、Discovery cleanup 和 executor 重建。
3. 同檔：真 fuse 才以 lock 增加 count。count 1/2 先 guard、等到 process age≥10.1 秒，再 `os._exit(75)`；count 3 留在 process、永久 guard。第三次鎖定後不可能安全自動取得有效幀，故只允許 count<3 的健康重啟窗口做 900s reset；鎖定須由明確管理動作在根因修復後清除。
4. `src/main.py`：若「只限 JKBMS 有效幀」是硬需求，在目前 listen 掛載呼叫（`src/main.py:904-926`）傳遞已知 `adapter_name`；dispatcher 現在未保存該資料。若任一有效 listen 幀均可，則無需此檔變更。
5. `.gitignore`：排除 `profile/.listen-watchdog.json` 及 `.lock`。不需變更 `docker-compose.yaml`；不清 adapter buffer、不重建 executor、不聲稱能殺 thread。

## 限制

- 模型已測 Host 檔案協定與 MQTT retained 語意，但沒有連接 broker、Docker、USB、TCP 或實際 JKBMS。
- Docker 端只做靜態確認；10.1 秒是依 012 修訂版提出的 arming 緩解。listen driver 初次 `connect()` 失敗仍在 dispatcher 建立前 `sys.exit(1)`（`src/main.py:698-734`），不屬此 counter 可修復範圍。
- 本輪只新增 `scratch/validation_017/` 與本報告，未修改 production source/config、Docker/Compose、container、hardware 或 MQTT。
