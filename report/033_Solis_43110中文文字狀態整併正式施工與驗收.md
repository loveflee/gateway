# Solis 43110 中文文字狀態整併正式施工與驗收

**日期：** 2026-08-11

# 人話結論

1. **本輪採 Solis 專用唯讀 Adapter。** 現有 profile／GenericAdapter 只能輸出多個 bit key，無法正確合併成兩個文字狀態；新 Adapter 只在 GenericAdapter 已成功讀出 43110 raw value 後加上文字，不碰 Modbus 或寫入。
2. **HA 已由十幾個實驗 binary_sensor 整理為三個唯讀 sensor：**「儲能控制模式」、「儲能控制附加功能」、「儲能控制原始值」。
3. **raw=1／33／35 解碼正確：** `1` 是「自用模式／無」；`33` 是「自用模式／市電充電功能…」；`35` 是「自用模式｜分時模式／市電充電功能…」，沒有被偷簡化成單一分時模式。
4. **未知 bit 保留：** `0x2001` 會顯示「自用模式」與「未知 Bit 13」；`0xFFFF` 會列出所有已知與未知 bit。
5. **原 `solis_inverter_map.yaml` 完全沒動。** SHA-256 與 HEAD 完全一致。
6. **沒有任何新的 43110 寫入能力。** map2 仍沒有 43110 setting／number entity，實測 `encode_write("set_storage_control", 1)` 被拒絕。
7. **map validator：PASS；HA Discovery fake-MQTT：PASS。** Discovery 精確只含三個 storage sensor、零舊 storage binary_sensor、零 command topic。
8. **實機唯讀：NOT TESTED。** 沒有修改或 restart runtime；目前 `config.yaml` 有使用者既有未提交修改，四台均指向 map2 但仍用 `rtu` adapter，不是安全的單一測試 UID，也不會選到本輪新插件。
9. **最終：PASS WITH LIMITATIONS。** 離線 decode、Discovery、plugin loading 都通過；啟用前仍需另案、明確授權地只切換一台測試 UID 到 `solis_inverter`，不得直接重啟四台正式設備。

## 2. 實際設計與 diff

### 2.1 Solis 專用唯讀 Adapter

[solis_inverter_adapter.py](/root/py_ginlong/adapters/solis_inverter_adapter.py:1) 註冊名稱為 `solis_inverter`，以 `Adapter(GenericAdapter)` 繼承所有既有成熟行為。它只覆寫 `decode()`：

```text
GenericAdapter 的 FC03／CRC／uint16 decode
→ 得到 set_storage_control raw value
→ 僅限 read_storage_control poll response
→ _decode_storage_control(raw)
→ storage_control_mode + storage_control_modifiers
```

它沒有 `encode_write()`、Driver、ACK、CRC、transport、reconnect、scheduler 或 MQTT 實作；這些全都由父類與既有模組處理。非 43110 command、verify response、invalid raw value 都直接保留 GenericAdapter 的行為。

### 2.2 Bitmask 文字規則

| 分組 | bits | 顯示規則 |
| --- | --- | --- |
| 模式 | 0 自用、1 分時、2 離網、4 備援／保留、6 饋網優先、11 削峰 | 依 bit 編號遞增，以 `｜` 串接；無 bit 為「無」。不判優先、不同步修正。 |
| 附加功能 | 3 電池喚醒、5 市電充電、7 電池 OVC、8 電池強制充電／削峰、9 電池電流校正、10 電池修復 | 依 bit 編號遞增，以 `｜` 串接；無 bit 為「無」。所有未本機證實的名稱保留「上游定義」標示。 |
| 未知 | 12–15，及未來未列入 known set 的 16-bit bit | 附加在 known modifiers 後方，格式「未知 Bit N」；絕不丟棄。 |

bit 5 完整文字固定為「市電充電功能（上游定義，極性未在本機確認）」，保留 [031 報告](/root/py_ginlong/report/031_Solis_43110儲能控制Bit定義與安全寫入敵對式審查.md:105) 已記錄的上游文件／field-capture 極性矛盾。

### 2.3 map2 最終 HA 結構

[solis_inverter_map2.yaml](/root/py_ginlong/profile/solis_inverter_map2.yaml:204) 的 B1 只新增／保留下列 43110 diagnostics：

| key | HA 名稱 | 類型 | command topic |
| --- | --- | --- | --- |
| `storage_control_mode` | 儲能控制模式 | sensor（文字 state） | 無 |
| `storage_control_modifiers` | 儲能控制附加功能 | sensor（文字 state） | 無 |
| `set_storage_control` | 儲能控制原始值 | sensor（raw uint16） | 無 |

已從 map2 移除：

- backend `storage_control_bits` sensor
- 全部 `storage_bit_*` B3 binary_sensor Discovery

map2 仍沒有 `settings[43110]`，也沒有 `B2_SETTING.set_storage_control` number entity；不會建立 43110 command topic。原穩定圖不受影響。

### 3.4 43110 寫入封閉

在 map2 + `solis_inverter` Adapter 中實際呼叫：

```text
adapter.encode_write("set_storage_control", 1)
→ ValueError
→ 43110 encode_write=REJECTED PASS
```

原因是 map2 沒有該 key 的 setting；沒有產生 request bytes，更沒有發出實機 write。新 Adapter 本身亦未新增 `encode_write()`。

### 3.5 HA Discovery（fake MQTT）

使用 in-memory fake MQTT client 實際呼叫 `HAManager.send_discovery()`：

```text
HA final discovery: 3 read-only text/raw sensors=PASS
storage binary sensors=0 PASS
command_topic=NONE PASS
```

斷言結果：

- 恰有三個 storage Discovery config，且都是 `sensor`。
- 名稱恰為「儲能控制模式」、「儲能控制附加功能」、「儲能控制原始值」。
- 三者都沒有 command topic。
- 不存在 `storage_bit_*` Discovery，也不存在 `number/.../set_storage_control/config`。

這只收集 Python method calls；沒有連到 MQTT broker，故不會產生或清除 retained Discovery。

### 3.6 HA state payload（fake MQTT）

將 raw=`35` 的實際 Adapter decode 結果交給 `HAManager.publish_state()`，fake MQTT 收到的同一份 JSON state payload 已斷言包含：

```text

storage_control_mode       = 自用模式｜分時模式
storage_control_modifiers  = 市電充電功能（上游定義，極性未在本機確認）
```

結果：`HA state payload raw=35 mode+modifiers=PASS`。這證明三個 Discovery entity 所引用的 state key 會實際一起出現在既有 state payload；沒有修改 HA Manager。

## 4. 實機、Discovery retained 與啟用限制

### 實機唯讀結果

**NOT TESTED。** 本輪沒有 restart、沒有寫入、沒有變更 config，故新 plugin 尚未由 running Gateway 載入。

需特別區分：working tree 的 `profile/config.yaml` 目前是使用者既有未提交狀態，四台 UID 都指向 map2、但仍是 `adapter: rtu`。即使重新啟動，它也不會選擇本輪的 `solis_inverter` semantic overlay；而且一次切換四台也不符合安全測試範圍。不得以此直接做實機驗收。

未來若要啟用，必須另案獲授權並採最小範圍：

1. 只指定一台已確認的測試 UID；
2. 將該 UID 的 adapter 改為 `solis_inverter`，其餘 UID 維持不動；
3. 重啟前備份／審查 config；
4. restart 後只讀觀察 raw、模式、附加功能三者一致；
5. 全程禁止對 43110 寫入。

### retained Discovery

profile 與 fake-MQTT 驗證證明「新程式不再發布」舊的 `storage_bit_*` config；若 HA 仍看到舊 entity，原因可能是 broker retained Discovery 歷史，不代表 map2 仍有 B3 定義。清理 retained topic 屬外部狀態變更，本輪未操作。日後需先列出目標 topics、確認影響，再取得授權逐一清除；不得用 wildcard 大範圍刪除。
