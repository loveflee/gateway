## P2 判定與版本比較

依任務所定順序，只有 P1 的每個命令皆有完整回覆才可切換 P2。P1 未達門檻，因此本輪**沒有**將 `6k2p2` 寫入 active profile，也沒有重啟進行 P2 實測。

前一輪 `6k2`（等價四組 P2）曾有 10 分鐘實機觀察：TCP 重組後四個合併命令共 25 個有效 TX request，但目標正常 RTU RX 為 0，成功率為 0.00%。詳見 [024 報告](/root/py_ginlong/report/024_6k2合併讀取實機10分鐘觀察報告.md)。

| 實機版本／觀察範圍 | 完整 RX / TX | 觀察成功率 | 結論 |
|---|---:|---:|---|
| P1 全部 13 命令（本輪） | 89 / 123 | **72.36%** | 最高，但未達逐命令門檻 |
| P1 `read_energy2_all`（本輪） | 6 / 8 | **75.00%** | 最小合併區塊有部分完整回覆 |
| P2 四組合併（前次） | 0 / 25 | **0.00%** | 無有效目標 RX |

因此，依已觀察資料，**P1 是 RX 解析成功率最高的合併版本**。不過兩輪試驗的日期、壓力流量與輪詢間隔不同（前次 P2 為 15 秒、本輪 P1 為既有的 10 秒），此比較是「觀察結果排序」，不是可證明 P1 必然優於 P2 的控制實驗。
